# 优秀 PRD 片段示例：AI 生成会议纪要

> 这个片段展示：一个 AI 功能如何用最少的篇幅，把「能力边界 + 可解释 + 验收」三件事说清楚。
> 它好在哪？看每段后的【注解】。

## AI 能力边界

可以：
- 总结会议内容（提取主题、结论）
- 提取待办事项（负责人 + 截止时间）
- 识别发言人观点

不能：
- 编造不存在的决定（会议没说的，AI 不能补）
- 修改会议结论（AI 是记录者，不是决策者）
- 替会议生成「行动建议」之外的衍生内容

【注解】边界不是空话「不编造」，而是列出**具体哪些动作禁做**。这是 AI 行为边界设计。

## 事实边界矩阵（节选）

| 内容类型 | 允许 | 说明 |
|---------|------|------|
| 会议结论表述 | ✅ | 可压缩、可重写 |
| 待办负责人 | ❌ | 必须来自录音 / 记录 |
| 待办截止时间 | ❌ | 必须来自录音 / 记录 |
| 决定内容 | ❌ | 未提及则留空，不生成 |

【注解】可证伪字段只读取不生成，直接卡死幻觉。

## 验收标准

```
Given 用户上传会议录音（≤2小时）
When 点击"生成纪要"
Then 系统输出包含：
  - 会议摘要（≤300字，覆盖主要议题）
  - 待办事项列表（每条含负责人+截止时间，且均来自录音）
  - 发言人及其观点（仅记录明确发言）
且：未提及的决定不出现在输出中
```

【注解】Given/When/Then + 可测项（≤300字、来自录音）+ 反向校验（未提及不出现）。测试一看就会写用例。

## 可解释性（三段式）

```
原内容：张伟说下周把方案给李娜。
识别为：待办事项
因此调整：负责人=张伟，对接人=李娜，截止=下周
```

【注解】理由只引用来源（原内容 → 识别 → 动作），无「提升专业感」类废话。

## 降级方案

| 等级 | 效果 | 接受 |
|------|------|------|
| A | 转写+总结全准 | 目标 |
| B | 转写准、总结偶有遗漏 | 可接受，提示用户核对 |
| C | 转写失败 | 不接受，提示重传或手动输入 |

【注解】模型能力不达标时 PM 已定决策，开发不临时问。

---
这个片段之所以「好」：
1. 边界具体（不是「不编造」三个字）
2. 验收可测（有数字、有反向校验）
3. 可解释（理由有来源）
4. 有降级（做不到怎么办提前定）
5. 篇幅短（一个功能一屏看完）
