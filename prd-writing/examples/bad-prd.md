# 差的 PRD 示例与修正

> 左边是真实常见的「AI 套模板」写法，右边是修正。每一处问题都对应一条原则。

## 原版（❌）

```
## 功能
增加 AI 能力，让系统更智能。

## 说明
使用大模型自动处理用户内容，提升用户体验。

## 目标
提高智能化水平，赋能业务闭环。
```

## 问题诊断

| # | 问题 | 违反原则 |
|---|------|---------|
| 1 | 不知道解决什么用户问题 | 原则1 用户问题优先 |
| 2 | 没有输入 / 输出定义 | ai-product-prd §1 |
| 3 | 没有能力边界 | ai-product-prd §2 |
| 4 | 没有错误处理 | 原则5 异常流程 |
| 5 | 没有验收标准 | acceptance-criteria §1 |
| 6 | 「更智能 / 赋能 / 闭环」无法测试 | 原则3 可验证 |

## 修正版（✅）

```
## 功能：AI 摘要生成

### 用户问题
运营每周要从 50 条用户反馈中提炼共性痛点，手动归类耗时 4 小时。

### AI 能力设计
输入：用户反馈文本（≤200条/次）
输出：按主题聚类的摘要（每条含代表原句引用）

AI 可以：聚类、提取高频词、总结
AI 禁止：编造反馈中不存在的观点、修改原句事实

### 验收
Given 上传 50 条反馈
When 点击"生成摘要"
Then 输出 ≤8 个主题聚类，每个含≥1条原句引用，
且未出现反馈中不存在的观点

### 指标
人工修改率 < 30%（目标可测）
```

## 一句话总结

差 PRD 的特征：加了「AI」两个字，其余全是形容词。
好 PRD 的特征：删掉「AI」两个字，仍然是一份清楚的需求文档。
