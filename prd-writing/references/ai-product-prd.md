# AI 产品 PRD 专项参考

> AI 产品或 AI 功能的 PRD，除了通用原则外，必须额外回答本文件的问题。对应 `SKILL.md` 的 Step 11 与 v0.2/v0.3 检查。

## 一、AI 输入与输出

- **AI 输入**：模型接收什么？（用户问题 / 文档 / 数据 / 系统上下文）
- **AI 输出**：输出什么？（文本 / JSON / 分类结果 / 建议）
- **输入要收窄**：明确边界，不要"模型可以读取一切"。

## 二、AI 能力边界（必写）

明确：
- **可以做什么**（如：基于用户真实内容重写表述、关键词突出、压缩篇幅）
- **不可以做什么**（如：编造事实、改动版式、生成全新结构、替用户决策）

> 反例："AI 自动优化简历" —— 边界模糊。
> 正例："AI 仅按 JD 改写文字内容；不编造经历、不碰排版、不生成新结构。"

## 三、事实边界：内容修改权限矩阵

AI 产品没有事实边界 = 没有护栏。用权限矩阵表达：

| 内容类型 | 是否允许改写 | 说明 |
|---------|------------|------|
| 句式 / 表达顺序 | ✅ 允许 | 措辞重写、语序调整 |
| 关键词突出 / 长度压缩 | ✅ 允许 | 根据需求调整重点、精简 |
| 公司名 / 职位 / 时间 / 数字成果 | ❌ 禁止 | 事实实体，只能读取不能编造 |
| 项目名 / 学校 / 证书 / 技术栈 | ❌ 禁止 | 事实实体，新增即幻觉 |

规则：允许同义表达、信息压缩、按需求调整重点；禁止新增数字、公司、职位、项目、职责、成果、时间、技术栈。

## 四、改写依据机制（交集原则）

AI 的改写/生成必须来自"**用户已有内容 × 需求**"的交集，不能自由发挥：

1. **提取**：从需求（如 JD）中提取要求与关键词
2. **匹配**：需求要求 × 已有内容 做交集，识别值得突出的内容
3. **生成**：仅基于交集内的内容进行表达重整
4. **依据留痕**：每段输出附带"匹配到的需求点 + 对应的原文片段"

> 反例："看到 JD 有 SQL 就硬塞 SQL" → 幻觉。
> 正例：只有原简历确实有 SQL 相关经历，才允许突出 SQL。

## 五、可解释性（防"理由"本身幻觉）

"理由"也是 AI 输出，同样可能编造。理由只能**三段式引用**：

```
原内容片段：xxx
需求要求：xxx
因此调整：xxx
```

- 不得自由解释、不得输出评价性说明（如"为了提升专业感"）
- 无法完成三段式引用的理由，不允许输出

## 六、幻觉控制（可定义、可测量）

至少考虑：
- 无依据时拒答
- 引用来源
- 事实一致性核对（改写后与原内容逐项比对）
- 人工确认：疑似编造段标记"需人工确认"，不自动落库

**指标要可定义**：不用"幻觉率=0"（无法证明、未定义何为幻觉）。
用："对于可验证事实字段（公司名/时间/数字/项目名），改写后不得新增原内容不存在的事实信息。计数 = 新增事实信息的改句数 / 总改句数，目标 0。"

## 七、AI 能力降级方案（必写）

模型能力可能达不到预期，PRD 必须提前定义「做不到怎么办」：

### 输出保真/质量等级表

| 等级 | 效果 | 是否接受 |
|------|------|---------|
| A | 完全达到目标效果 | 目标 |
| B | 接近目标，少量复杂场景降级处理 | 可接受（需向用户明示） |
| C | 退化为非 AI 方案 | 视产品而定，需明确 |

### 降级路径
- **人工确认**：AI 结果存疑时由用户确认
- **回退**：AI 能力不足时回退到原内容/原流程
- **提示用户**：明确告知当前限制
- **降低自动化程度**：从"全自动"降为"半自动 + 人工把关"

> 原则：降级方案必须在 PRD 阶段定义，不能让开发在"做不到怎么办"上替 PM 做决策。

## 八、人机协作方式

明确哪些环节**自动**、哪些环节**人工**：
- 示例：AI 自动生成改句 → 用户逐段采纳/拒绝 → AI 只产出"待确认"结果，不直接覆盖最终文件

## 九、AI 指标（可定义、可测量）

| 指标 | 可定义写法 | 不可写 |
|------|-----------|--------|
| 事实新增率 | 新增事实信息的改句数 / 总改句数，目标 0 | 幻觉率 = 0 |
| 用户采纳率 | 采纳改句 / 总改句 | 接受度好 |
| 人工修改率 | 用户改动过的改句比例 | 改动少 |
| 理由可引用率 | 满足三段式引用的改句占比 | 解释清楚 |
| 延迟 | 单次调用耗时 | 响应快 |

## 十、常见坑

- ❌ "AI 生成高质量总结" → 无法验收
- ❌ "调用大模型生成" → 没写输入/输出/失败处理
- ❌ "让 AI 自由发挥" → 没有依据交集
- ❌ 只写 AI 能做什么 → 不写 AI 失败时怎么办
- ❌ 把技术实现写进 PRD（python-docx、RAG 具体方案） → 放技术方案文档
