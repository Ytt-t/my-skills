# my-skills

> 一套**从 0 到 1 的 AI 产品方法论 skill 库**，覆盖"发现需求 → 拆解竞品 → 写 PRD → 设计架构 → 埋点验证"的完整产品生命周期。
>
> 由 AI 产品经理视角打磨，每个 skill 都强调：**不堆技术、不抄功能、围绕真实用户问题和业务价值做决策**。可作为个人作品集，也可直接复制进 Agent 使用。

## 每个 Skill 详解

### ① requirement-analysis — 需求分析专家
帮你从模糊的想法，深入到"解决谁的问题、是否值得做、如何验证"。核心能力：
- **证据分级**：已知事实 / 合理推断 / 待验证假设 / 当前未知，绝不把推断包装成事实。
- **替代方案分析**：强制问"不做这个产品，用户还有什么办法"，防止伪需求。
- **范围边界**：明确"做什么"和"不做什么"。
- **需求拒绝机制**：敢说"当前没发现明确的高频强价值问题，建议暂不进入设计"。

### ② pm-ai-competitor-deconstructor — AI 竞品拆解与机会分析
拆解竞品的定位、AI 能力、用户体验和差异化机会。核心能力：
- **AI 能力拆解**：输入能力 / AI Workflow（Prompt Chain · Agent · Tool Calling · RAG · Memory）/ 可靠性设计。
- **用户体验拆解**：Onboarding、AI 交互、用户控制权。
- **双矩阵输出**：AI 能力矩阵 + 用户体验矩阵，一目了然。
- **机会分析**：可借鉴点 / 不建议复制 / 差异化机会（痛点-缺口-方案-MVP）。
- **可直接转化为 PRD**：输出产品机会、目标用户、核心场景、AI 能力、用户流程、关键指标。

### ③ prd-writing — PRD 编写
把已经明确的需求，整理成可评审、可设计、可开发的 PRD。核心能力：
- **技术 / 产品分离**：技术细节移交独立方案，PRD 聚焦产品价值。
- **事实边界矩阵**：明确 AI 能改什么、不能改什么（如简历改写中"数字/公司名禁改"）。
- **降级方案前置**：在"做不到怎么办"上提前替团队做决策。
- **可解释 + 可测量**：改写理由三段式、指标必须可定义可测。
- **配套齐全**：`references/`、`templates/`、`examples/`、`evaluations/` 可直接复用。

### ④ pm-ai-architecture-designer — AI 架构设计助手
从需求、场景、用户问题出发，设计完整 AI 系统架构。核心能力：
- **四类架构模式**：Prompt 应用 / RAG 知识增强 / Agent 智能体 / Multi-Agent 系统，按需求选型。
- **分层架构图**：用户层 → 应用层 → AI 编排层 → 能力层 → 模型层 → 数据层。
- **模型选型 + Prompt 设计 + Agent 设计**：含 Tool 定义规范。
- **评估体系 + 异常安全**：模型效果 / 产品指标 / 成本指标，幻觉 / 错误输出 / 隐私方案。
- **12 节输出模板**：从产品目标到迭代路线全覆盖。

### ⑤ pm-tracking-spec-writer — 埋点与指标设计
把"上线后怎么衡量效果"提前设计好。核心能力：
- **用户链路拆解**：行为层 + AI 过程层双视角。
- **事件设计规范**：分类、命名规范、字段字典。
- **AI 核心指标体系**：使用 / 效果 / 质量三类指标。
- **AI 特殊事件模板**：如 `ai_request_success`、`ai_output_feedback`。
- **QA 验收清单 + 输出文档结构**，可直接交付数据/开发。

## 怎么用

**作 Agent 的 Skill**：把对应 `SKILL.md` 的内容直接复制进你的 Agent（如 WorkBuddy / Cursor / Coze / Dify），即可获得该角色的方法论。

**作方法论参考**：每个 skill 本身就是一份高质量的产品方法论文档，可直接用于面试讲解、作品集展示、团队规范对齐。

**作产品流水线**：按 ① → ② → ③ → ④ → ⑤ 的顺序串起来，就是一个完整 AI 产品的从 0 到 1 工作流。

---

> 设计理念：**拆解不是为了复制，而是为了发现机会；架构不是堆技术，而是围绕业务目标设计最合适的人机协作系统。**
